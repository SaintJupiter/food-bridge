# 食间桥 · 双平台联动 Web Demo

唯一主交付物是网页。React + TypeScript + Vite，无真实平台API、账号、订单或埋点服务。

## 运行

`npm ci` 后 `npm run dev`，打开 http://127.0.0.1:4190/ 。`npm run build` 生成 dist，可静态部署。

## 三分钟演示

1. 点击「01 被种草，去下单」→ 打开食记 → 去吃了么看看 → 精确进入椒麻鸡饭 → 加购。
2. 点击「02 犹豫，先看看」→ 布丁加购 → 看看社区怎么说 → 返回吃了么 → 购物车保留 → 完成模拟订单。
3. 点击「03 同名，不错绑」→ 查找候选 → 两个木木咖啡分店同分，不能自动发布 → 选分店与菜品 → 确认关联。

社区首页参考用户提供截图的信息层级：频道/搜索/双列瀑布流；外卖首页为地址/搜索/分类/商家列表。品牌及素材原创，不复制真实平台内容。

## 真实边界

- 12家虚构门店、45个SKU、15篇精选初始笔记、20张独立生成图（10张社区写实图 + 10张外卖像素画）。首7篇社区笔记图片互不重复；全社区首页每图最多2次，仍不是真实用户照片。
- 匹配是名称与分店规则；不运行Embedding或图像模型，不把规则分数叫概率。
- 图片/评价数量是人工构造场景统计；AI插画不计入真实实拍。
- 跨App跳转实际为单SPA内路由切换。保留当前会话购物车，刷新会重置；没有真实第三方Deep Link。
- 发布、关注、收藏、订单与日志只在内存。仅本地演示，不发送到服务器。
- 错误匹配率和订单提升未经实验，不给出虚假指标。分析页仅展示本次操作事件次数。
- 已有加载、无结果、分店冲突、故障模拟、关联开关。尚无PWA离线缓存、真实登录、上传、支付及平台合作。
- 开发模式的布局切换放在幕后机制的折叠区，避免遮挡手机内容；生产隐藏。两端底栏已独立，演示设备层提供应用切换，跨端CTA展示应用过渡。

## 素材

内置 imagegen 生成 `public/assets/{chicken,pudding,noodles,dumplings,cake,salad,latte}.png`，各自独立图片并用 `object-fit: cover` 等比裁切，不再把四象限背景拉伸。完整提示词见 `docs/asset-prompts.json`，概要：自然光食物摄影、单幅居中、无人物文字品牌、保留餐具边缘。旧图保存在 `archive/assets/food-atlas-v1.png`，不再发布。元数据见 src/data.ts 的 mediaManifest。

外卖端配对的 `public/assets/pixel/*.png`，共10张中颗粒像素画；完整生成提示词见 `docs/pixel-prompts.json`。通过独立渲染上下文切换素材，不更换菜品实体。视觉参考与取舍见 `docs/visual-direction.md`。外围近白暖底，社区莓果红+高清图，外卖亮蓝+紫色推荐区+彩色像素分类。正文保持普通清晰字体。

## 本轮检查（2026-09-26）

- 原因与修正：共用底栏 → 两端独立导航；循环4张图/48篇 → 7图/12篇精选；背景分别缩放宽高 → 独立图片等比裁切。
- 额外修正：首页返回丢筛选、旧来源标记污染别的菜品、返回同菜的错误笔记、搜索按钮无行为、区域筛选后推荐横幅错店、重复同菜缩略图、加购提示不消失。
- 浏览器实测：搜索无结果与恢复、分类、收藏/关注、筛选保留、两端切换、内容→菜品→原笔记、外卖→社区→返回→购物车→模拟订单、同名与冲突分店、确认发布、撤回关联、跳转失败恢复。桌面与390px手机截图检查通过，图片等比裁切、手机无横向溢出。
- `node --test tests/data.test.mjs tests/delivery-search.test.mjs`：8/8通过；`npm run build`通过。测试只覆盖原型边界，不代表真实平台或模型评测。
- 后续边界：尚未做真实用户可用性实验、真实跨App集成、模型接入与生产部署性能压测；生成图在不同门店仍有有限复用。

### 鲜明配色迭代

- 问题：温馨背景被错误扩大成全站低对比黄棕滤镜。修复：替换主题，按社区/外卖/关联/购物车/边界分别配色；保留摄影和像素两套素材。
- 浏览器复现：搜布丁却展示鸡饭/咖啡图；搜拿铁仍显示全店 ¥18 起。原因：过滤门店、预览菜单与价格各自计算。修复：`deliveryResults` 统一命中菜单，驱动图片、菜名、价格和排序；新增3项回归测试。
- 可用性：技术 ID 收进折叠区，默认解释菜名与分店；撤回授权后明确发布阻断原因；故障按钮改称“关闭故障模拟”，不暗示已自动重试；手机演示指南默认收起。
- 本轮实测：搜索/分类/区域/空态恢复，外卖→社区→原菜品→保留购物车→模拟订单，确认分店发布→故障→恢复→返回原帖，关注/收藏，撤回授权禁用发布。1440px桌面、390px及320px手机检查；无横向溢出，图片使用等比裁切。
- 仅原型会话验证，不声称真实转化或推荐效果提升。

### 产品布局与社区语义修正

- 双 App 命名为“老红书 / 吃了么”，均为虚构概念品牌，与现实平台无关联。路由和原有实体 ID 保持不变。
- 社区主入口“关注 / 发现 / 同城”；兴趣主题为“推荐、美食、探店、咖啡甜品、一人食”，由笔记主题驱动，不再把菜名当社区频道。具体菜名保留在搜索和关联信息中；没有做饭内容，不为了凑导航增加空的做饭频道。同城仅使用固定演示商圈，不读取定位。
- 外围重排：浅紫体验引导 → App + 产品痛点/设计依据 → 机制/状态 → 验证计划。不将原方案中的假设写成已验证研究结果。
- 门店增加像素主视觉、门店信息、点餐/菜品评价/门店信息栏目、分类菜单、快捷加购与会话购物车。无真实评价文本、优惠承诺、履约或支付。
- 新增披萨/寿司/抹茶各一张写实图与像素图；提示词见 docs/menu-v5-prompts.json。新 SKU 追加，不改变原 d0–d35 的身份。
- 自动化：三个测试文件共 12 项通过（社区主题/关注/商圈/菜名搜索/新增 ID/图片/规则边界/外卖搜索）；生产构建通过。仅原型检查，不代表真实业务效果。
